# VisionAgent Android 开发路线图

本文档定义 VisionAgent Android 从 0 到 1 的完整开发任务。路线图按产品可用性推进，而不是按技术炫技排序。

## 最终理想形态

VisionAgent Android 的理想形态是一个安全、可控、可观察的手机 Agent：

1. 能理解当前屏幕。
2. 能拆解用户任务。
3. 能检索本地策略和历史失败经验。
4. 能每轮只执行一个可验证动作。
5. 能识别失败、重复、风险和页面不确定性。
6. 能在高风险动作前请求用户确认。
7. 能沉淀 App 专项策略，逐步提升成功率。
8. 能在隐私敏感场景优先本地处理。

## 阶段 0：工程基线

目标：保证项目可以稳定构建、测试、运行和回归。

任务：

- 统一项目命名、包名、文档和配置。
- 清理过时 Demo 代码和过时文档。
- 建立最小单元测试集。
- 明确 API Key 只放在 `local.properties`。
- 建立 GitHub 主分支上传流程。

验收标准：

- `./gradlew :app:assembleDebug` 成功。
- `./gradlew :app:testDebugUnitTest` 成功。
- 仓库不包含 API Key。
- README 能准确描述当前能力和限制。

当前状态：基本完成。

## 阶段 1：屏幕感知和执行闭环

目标：Agent 能稳定观察屏幕并执行低风险动作。

任务：

- 完成 `EdgeAgentAccessibilityService`。
- 完成 `ScreenCaptureService` 持续帧缓存。
- 提取文本化 UI 树。
- 提取结构化 `UiNode`。
- 支持点击、长按、滑动、返回、Home、最近任务。
- 支持文本输入。
- 支持打开 App。
- 增加坐标越界校验。

验收标准：

- 能打开系统设置。
- 能执行返回、Home、滑动。
- 能在输入框中填入文本。
- 截图不可用时，Agent 能降级为 UI 树模式。
- 坐标越界动作不会执行。

当前状态：基础完成，真机兼容性待验证。

## 阶段 2：RAG 策略记忆

目标：模型决策前能获取本地策略，减少自由发挥。

任务：

- 实现 `LocalRagEngine`。
- 定义 `RagDocument` 和 `RagHit`。
- 内置微信草稿策略。
- 内置高风险动作确认策略。
- 内置系统设置策略。
- 内置浏览器搜索策略。
- 将 RAG 结果注入 prompt。
- 增加 RAG 单元测试。

验收标准：

- 微信发消息任务能命中“只填草稿”策略。
- 支付、提交、下单任务能命中高风险确认策略。
- Agent prompt 中包含检索到的本地策略。

当前状态：基础版完成。

下一步：

- 用 Room 持久化策略。
- 接入文本 Embedding。
- 保存失败样本并可检索。
- 加入用户偏好记忆。

## 阶段 3：多 Agent 协作

目标：把单体 Agent 拆成规划、执行、反思、安全四个角色。

任务：

- `PlannerAgent`：识别任务类型、目标 App、安全模式。
- `ReflectionAgent`：识别连续失败、重复动作、连续等待、不可观测状态。
- `ActionGuard`：执行前拦截高风险动作。
- `AgentExecutor`：接入规划、RAG、反思和安全守卫。
- 输出更清晰的进度状态。

验收标准：

- 微信任务默认草稿模式。
- 高风险最终按钮不会自动点击。
- 连续失败时 Agent 会改变路径或停止。
- 连续 WAIT 不会无限循环。

当前状态：基础版完成。

## 阶段 4：任务安全和用户确认

目标：把安全策略从代码拦截提升为用户可理解的产品流程。

任务：

- 增加 `PendingUserConfirmation` 状态。
- 增加确认弹窗或底部确认面板。
- 展示即将执行的动作、目标 App、风险原因。
- 用户确认后才执行高风险动作。
- 用户拒绝时记录失败样本。

验收标准：

- 发送消息前必须确认。
- 支付、提交、删除、转账前必须确认。
- 确认弹窗说明动作来源和风险。
- 拒绝后 Agent 不继续执行同类动作。

## 阶段 5：失败日志和回放

目标：把调试从看 logcat 升级为可回放的任务轨迹。

任务：

- 定义 `AgentTrace`。
- 保存每轮截图状态、包名、UI 树摘要、RAG 命中、模型输出、执行结果。
- 失败时导出 JSON。
- 增加失败样本列表页。
- 支持将失败样本写入 RAG。

验收标准：

- 任意失败任务可定位到具体轮次。
- 能看见模型为什么点错。
- 能把失败样本转成后续策略。

## 阶段 6：App 专项策略

目标：不要让模型自由探索复杂 App，而是用状态机约束。

优先 App：

1. 系统设置。
2. 浏览器。
3. 微信草稿。
4. 联系人。
5. 地图搜索。
6. 美团搜索。

微信策略边界：

- 允许打开微信。
- 允许搜索联系人。
- 允许进入聊天页。
- 允许填草稿。
- 禁止自动点击发送。

验收标准：

- 每个 App 有明确 `AppStrategy`。
- 每个策略有状态枚举和允许动作集。
- 模型只能在允许动作集内选择。
- 策略失败时能回退。

## 阶段 7：持久化 RAG 和向量检索

目标：从内置关键词策略升级到可成长的记忆系统。

任务：

- 引入 Room。
- 建立策略表、失败样本表、用户偏好表。
- 引入轻量文本 Embedding。
- 支持相似任务检索。
- 支持失败样本自动进入检索库。

验收标准：

- 同类失败不重复发生。
- 相似任务能检索到历史成功路径。
- 用户偏好能影响任务计划。

## 阶段 8：本地模型能力

目标：降低云端依赖，提升隐私和离线能力。

任务：

- 抽象 `ReasoningEngine`。
- 本地规则引擎优先处理确定性任务。
- 评估端侧 VLM。
- 评估本地小模型或 OCR。
- 云端只处理复杂视觉和复杂规划。

验收标准：

- 打开 App、系统设置、设备控制不依赖云端。
- 简单 UI 元素定位可本地完成。
- 云端不可用时仍有基础功能。

## 阶段 9：产品体验

目标：从工程 Demo 变成可用产品。

任务：

- 增加任务运行面板。
- 展示当前轮次、当前 App、下一步动作。
- 增加暂停、取消、继续。
- 增加确认弹窗。
- 增加失败回放入口。
- 增加权限状态诊断。

验收标准：

- 用户能理解 Agent 正在做什么。
- 用户能随时停止任务。
- 失败时能看到明确原因。

## 阶段 10：评测体系

目标：用可量化指标驱动迭代。

指标：

- 任务成功率。
- 平均轮数。
- 平均耗时。
- 误点击次数。
- 安全拦截次数。
- 截图失败率。
- UI 树可用率。

任务：

- 建立测试任务集。
- 建立每次提交后的手工验收清单。
- 建立真机兼容性矩阵。
- 记录不同 ROM 上的问题。
